### 잘된 점

- Host exhaustive 검증과 target representative HIL의 책임 경계를 명확히 분리했다.
- 실패를 숨기지 않고 review blocker를 실제 결함으로 처리했다.
- HIL PASS 출력을 awaited CAN receipt에 묶어 “출력만 PASS”인 허위 양성 가능성을 제거했다.
- firmware hash, flash operation ID, raw TT_Host receipt, CAN transcript를 함께 보존해 구현→binary→flash→실행의 추적 사슬을 완성했다.
- 사용자의 “DUT 하나만 유지” 지시를 즉시 반영해 유휴 G4 claim을 반환했다.

### 주요 장애와 교훈

1. **Adapter FD flag 누락**
   - `MDL_FdCan_Frame_Fd`가 `SC_FRAME_FD`로 전달되지 않아 최초 FD 주장이 실제 FD 경로를 검증하지 못했다.
   - 교훈: payload 길이만으로 FD 경로를 추론하지 말고 flags/identifier까지 end-to-end로 검증해야 한다.

2. **수신 영수증 없는 PASS marker**
   - freshness/mux/extended 일부 문구가 target 관찰 없이 출력됐다.
   - 교훈: HIL의 PASS는 반드시 물리적 송수신 또는 target state receipt에 바인딩해야 한다.

3. **Runtime 동기화 drift**
   - `--overwrite-runtime` 누락으로 sibling firmware가 이전 runtime을 계속 사용했다.
   - BIN hash 불변을 통해 이를 발견했다.
   - 교훈: source sync 후에는 byte identity와 firmware hash 변화를 모두 확인해야 한다.

4. **Activation 안전성 결함**
   - corrupted active state를 pending-TX scan 전에 검증하지 않아 OOB read 위험이 있었다.
   - pool span multiplication wrap도 alias check 이전에 차단해야 했다.
   - 교훈: activation preflight는 caller-owned state를 신뢰하지 않고 산술 overflow 이전에 모든 구조적 조건을 검증해야 한다.

5. **증거 보존 미흡**
   - 최초 최종 flash의 operation receipt와 CAN transcript를 narrative로만 옮겨 review에서 반려됐다.
   - raw JSON receipt 5개와 35-PASS transcript를 직접 보존한 후 승인됐다.
   - 교훈: 최종 검증은 요약보다 원본 machine artifact가 우선이다.

### 운영상 개선점

- 처음부터 final-quality-gate JSON 스키마와 current-attempt evidence 경로를 준비했으면 종료 단계의 추가 작업을 줄일 수 있었다.
- 보고서 identity를 구현 head, docs head, sibling head로 명확히 분리해야 stale hash 혼동을 방지할 수 있다.
- shell success marker는 `echo`/`printf`로 출력해야 하며, bare token을 command로 실행해 전체 성공 후 exit 127을 만드는 실수를 피해야 한다.
- HIL transcript와 TT_Host receipt는 실행 시점부터 evidence 디렉터리에 직접 저장하는 편이 안전하다.
